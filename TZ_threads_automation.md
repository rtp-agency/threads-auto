# ТЗ: Система автоматизации контента и аналитики для Threads

## Контекст

Клиент — эксперт/специалист, ведёт Threads-аккаунт как канал лидогенерации на свою услугу (ниша задаётся в BASE_SYSTEM). Топ-контент — личные истории/провокации с вопросом к аудитории (архетип "POV + инфоповод"). Нужна система: сбор метрик → анализ голоса → генерация черновиков в стиле клиента → апрув через Telegram-бот → автопостинг.

Разворачивается как ещё один сервис в существующем Docker-стеке (FastAPI + Celery + PostgreSQL + Redis, аналогично PostForge). Переиспользуй существующие паттерны проекта (slot-isolation промптинг, каскад моделей, структура миграций) там, где это применимо.

---

## 1. Threads API — интеграция аккаунта

- Регистрация Meta Developer App, use case "Access the Threads API".
- Auth-модель: **Threads Tester** (не полноценный App Review) — клиент добавляется тестером по username, принимает инвайт, дальше доступны все нужные permissions без ожидания ревью.
- Permissions: `threads_basic`, `threads_content_publish`, `threads_manage_insights`.
- OAuth flow: короткоживущий token → обмен на long-lived (60 дней).
- **Celery beat job**: рефреш long-lived токена до истечения (аналогично существующему рефрешу токенов в PostForge).
- Endpoints: получение списка публикаций, insights по media_id (views/likes/replies/reposts/quotes), публикация через двухшаговый flow: create container → (задержка ~30 сек) → publish container.
- Хранить токены зашифрованными, не в открытом виде в БД.

## 2. Схема данных (PostgreSQL)

Таблицы (черновая схема, уточнить типы под ORM проекта):

```
accounts(id, threads_user_id, username, access_token_encrypted, token_expires_at, created_at)

posts(id, account_id FK, threads_media_id NULLABLE, source ENUM['generated','client_own'],
      archetype ENUM['pov_confession','educational','trend_reaction','meme_notification'],
      text, image_url NULLABLE, status ENUM['draft','approved','published','rejected'],
      created_at, published_at)

post_metrics(id, post_id FK, views, likes, replies, reposts, quotes, fetched_at)
  -- снапшоты во времени, не перезапись — нужно для скорости роста (2ч/6ч/24ч)

voice_profile(id, account_id FK, profile_text, examples JSONB, updated_at)
  -- profile_text: описание голоса/стиля; examples: verbatim цитаты для few-shot

post_embeddings(post_id FK, embedding VECTOR(...))
  -- pgvector, для retrieval похожих топ-постов при генерации

trend_topics(id, headline, source_url, fetched_at, relevance_score, used BOOLEAN)
  -- кандидаты на архетип trend_reaction, после LLM-фильтрации

avatar_pool(id, image_url, created_at)
  -- синтетические (не узнаваемые реальные люди) аватары для архетипа meme_notification
```

## 3. Сбор метрик (Celery beat)

- Периодичность: не реже раза в сутки (можно чаще в первые часы после публикации для отслеживания скорости роста).
- Тянет insights по каждому посту со статусом `published`, пишет новый снапшот в `post_metrics`.
- Считает `engagement_rate = (likes + replies + reposts) / views` для ранжирования в отчётах.

## 4. Источник актуальных тем (trend_topics)

- Celery job раз в день: тянет заголовки из новостного агрегатора (Google News UA RSS или аналог + 2-3 профильных телеграм-канала, если есть техническая возможность парсинга).
- LLM-фильтр (Claude Haiku): из сырых заголовков отбирает те, что годятся под формат "личная история клиента + актуальное событие". Большинство заголовков отсеивается — фильтр должен быть строгим, не любая новость подходит под архетип.
- Отобранные темы (2-3 шт) кладутся в `trend_topics`, бот предлагает их клиенту при запросе генерации архетипа `trend_reaction`.

## 5. Voice Profile

**Важно: это НЕ часть production-пайплайна.** Voice Profile — разовая (или редкая, при дрейфе стиля) ручная операция при онбординге клиента, выполняется через Claude Code, а не отдельным API-эндпоинтом в сервисе. Строить для неё автоматизированный флоу — избыточная инженерия для задачи, которая происходит один раз.

Процесс:
1. После получения Threads Tester доступа — скрипт (пишется через Claude Code) тянет **весь** архив постов клиента через Threads API (не выборочные скриншоты) и сохраняет в структурированный файл (JSON/markdown): текст + метрики (просмотры/лайки/комменты/репосты) + дата каждого поста.
2. Этот файл целиком скармливается Claude (в чате или через Claude Code) с промптом: не переписать посты, а **описать голос** — длина предложений, регистр/сленг/мат, структура (хук → история → вопрос к аудитории), пунктуация, ритм.
3. **Явно указать в промпте**: не сглаживать резкость/сленг до вежливого корпоративного тона — частая проблема, если не указать явно.
4. В профиль обязательно кладутся 3-5 verbatim примеров постов (few-shot), не только пересказ стиля текстом.
5. Результат вручную вычитывается и корректируется (контроль качества перед продакшеном), затем сохраняется как статичный текст в `voice_profile.profile_text` — это то, что реально читает система при каждой генерации.
6. Скриншоты-мокапы (архетип `meme_notification`) в анализ голоса не включать — это не органическая фотография со стилем, а отдельно описываемый текстом формат ("клиент любит такой архетип"), картинки модели для этого скармливать не нужно.
7. Повторная генерация — по запросу клиента через бота либо вручную через Claude Code, если стиль "уходит" со временем.

## 6. Few-shot retrieval

- При каждом запросе на генерацию: эмбеддинг темы/архетипа → поиск топ-3 похожих постов по `post_embeddings` с лучшим `engagement_rate` → кладутся в промпт как few-shot вместе с voice profile.

## 7. Генерация текста (каскад моделей)

- **Классификация архетипа / фильтрация новостей / разметка корпуса** → Claude Haiku (дёшево, быстро).
- **Voice Profile (разово) и финальная генерация постов** → Claude Sonnet. Рассмотреть A/B с Opus на первых 10-20 генерациях, если качество Sonnet недостаточно на этом специфичном голосе (разговорный украинский).
- Архетипы генерации: `pov_confession`, `educational` (разбор грамматики/лексики в стиле клиента), `trend_reaction` (тема из `trend_topics`), `meme_notification` (текст сообщения для скриншота-мокапа).
- По запросу `/generate` — 3-5 черновиков за раз, разных архетипов, не один вариант.
- Использовать prompt caching для voice profile + system prompt.

## 8. Генерация изображений (архетип meme_notification)

- Для архетипа "скриншот переписки/уведомления" — отдельный вызов image-API (Gemini или GPT image) с промптом: тип уведомления (Telegram/monobank/SMS), имя отправителя, текст, эмодзи, стиль "iOS lock screen notification".
- **Аватары**: не генерировать заново на каждый пост. Разово сгенерировать пул 15-20 синтетических (не узнаваемых реальных людей — важно: не использовать лица знаменитостей/актёров) аватаров, сохранить в `avatar_pool`, при генерации брать случайный.
- Если картинка вернулась с нечитаемым/кривым текстом — доступна ручная перегенерация (кнопка в боте), не полагаться на автоматическую валидацию текста на картинке в MVP.

## 9. Telegram-бот (aiogram 3, интерфейс)

Команды/кнопки:
- `/start` → главное меню: 📊 Статистика / 📝 Черновики постов
- **Статистика**: просмотры/взаимодействия/подписчики за период, топ-посты, разбивка по архетипам (для оценки "тестирования форматов" из требований клиента).
- **Генерация**: показывает черновик (текст + картинка, если архетип с изображением) одной карточкой с кнопками:
  - ✅ Опубликовать → в очередь на автопостинг
  - ✏️ Редактировать → следующим сообщением клиент присылает новый текст, заменяет черновик
  - ❌ Отклонить
  - 🔄 Перегенерировать фото (если применимо)
- **Добавить свой пост**: отдельная команда — клиент присылает свой текст, он идёт в ту же очередь на публикацию и в `post_metrics` наравне со сгенерированными (item "интеграция собственных постов" из требований).
- Еженедельный отчёт — проактивное сообщение от бота (не по запросу), см. ниже.

## 10. Автопостинг

- После ✅ в боте → Celery task: create container → publish container через Threads API.
- Публикация не позднее 15 минут после апрува (SLA из SOW).
- Обновить `posts.status = 'published'`, `published_at`.

## 11. Еженедельный отчёт

- Celery beat, раз в неделю, отправка в бот: просмотры, вовлечённость, рост подписчиков, сравнение перформанса по архетипам (`pov_confession` vs `educational` vs `trend_reaction` vs `meme_notification`).

---

## Вне скоупа MVP (явно не реализовывать)

- Публикация на других платформах, кроме Threads.
- Автоматический мониторинг контента конкурентов (только сбор новостных инфоповодов, см. п.4).
- Интеграция с CRM/платёжными системами школы.
- Автоматическая валидация читаемости текста на сгенерированных изображениях (только ручная кнопка перегенерации).

## Критерии приёмки (сверить с SOW перед сдачей)

- Тестовый запрос к Threads API успешно возвращает список постов; тестовая публикация проходит.
- Voice profile утверждён клиентом как соответствующий его стилю.
- Бот ежедневно предлагает 2-3 темы под архетип `trend_reaction`.
- Метрики обновляются не реже раза в сутки.
- Из 10 сгенерированных черновиков не менее 7 клиент оценивает как "не требует существенной правки".
- Все команды/кнопки бота работают без ошибок в тестовом прогоне с клиентом.
- Изображение прикладывается к черновику как единая карточка; кнопка перегенерации работает.
- Публикация — не позднее 15 минут после апрува.
- Еженедельный отчёт приходит в согласованный день.
